## Order that minimises risk
1. Code signing certificate (#1) → rebuild → read the signature step. 2. Staging S3: privacy + delivery checks (#2). 3. Migrations + env on staging, `spell-release-config-check` (#4).
4. Verify the real installer bytes with `spell-verify-installer` (#2). 5. Human Windows test on 10 and 11 (#5). 6. One small live QPay payment (#3). 7. Live activation smoke (#4). 8. Only then talk about a public release.

## Things no script can prove
Bucket privacy is configuration (Block Public Access, policy, ACL): the strict check *observes* it, an operator must *set* it. A code-signed installer cannot be produced
without the certificate. Real payment and real IME typing need a real merchant account and a real keyboard.
